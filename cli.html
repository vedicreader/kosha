cli

The kosha shell command: every index and graph query as a subcommand.

Agents that work through a shell, and people at a terminal, need kosha without writing Python. This module provides one kosha command with a subcommand for each query: sync, status, context, repo-context, env-context, ni, public-api, api-paths, dep-stack, top-nodes, where-to-add, watch, daemon, install, nuke, embed and prune. Subcommand names use hyphens where the Python methods use underscores, and so do flags, as in --as-json and --busy-timeout. A flag that is on by default is turned off with --no- in front, as in kosha sync --no-graph.

Output is readable markdown. --as-json prints JSON instead, for piping into jq or another program. kosha <subcommand> --help lists a subcommand’s flags.

kosha sync brings the index up to date, with the same switches as Kosha.sync: --no-repo, --no-env and --no-graph skip a part, --pkgs names the packages to index as a comma-separated list, and --force re-reads everything. To index packages in parallel, pass both --pkg-parallel and --busy-timeout 30000. When it finishes it prints the index status.

sync

def sync(
    dir:str=None, # directory to sync; defaults to repo root
    pkgs:str=None, # comma-separated package names; defaults to all pyproject.toml deps
    repo:bool=True, # index the repo
    env:bool=True, # index installed packages; --no-env indexes the repo only
    graph:bool=True, # build the call graph
    graph_mode:str='fast', # 'full' re-extracts changed files in worker processes
    graph_metrics:bool=True, # recompute PageRank after the graph update
    parallel:bool=True, # run repo, env, and graph sync in parallel
    embed:bool=True, # compute embeddings; --no-embed stores chunks for keyword search only
    force:bool=False, # re-sync everything, graph included, rather than what changed
    busy_timeout:int=None, # ms to wait on a locked db; set (e.g. 30000) when syncing in parallel
    pkg_parallel:bool=False, # index packages in parallel threads; needs --busy-timeout
    as_json:bool=False, # output the post-sync status as JSON
):

Index the repo, the installed packages and the call graph, then print the index status.

kosha context "query" runs Kosha.context, the combined search over the repo and the packages, and prints each hit with its name, line, PageRank, the first 300 characters of its source and up to five callers. The query can carry key:value filters. A filter-shaped token with an unknown key, such as libr:litesearch, prints a warning on standard error, because it is searched as text and does not filter anything. repo-context and env-context search one index only.

The graph subcommands take full dotted names. kosha ni fastcore.basics.merge prints a node’s PageRank and up to ten of its callers, callees and co-dispatched peers. public-api, api-paths, dep-stack and top-nodes print the results of the Kosha methods of those names; dep-stack with no --seeds starts from the packages in pyproject.toml. kosha watch re-indexes files as they change, until Ctrl-C.

kosha where-to-add "description" prints path:line suggestions for where new code should go, with the peers it would join. kosha nuke deletes the repo’s index and call graph, and kosha nuke --env also deletes the shared package and docs indexes.

kosha embed embeds the package chunks stored without an embedding, by sync --no-embed or an older kosha, a batch at a time; stopping it loses at most one batch. kosha prune removes the packages and versions that no indexed environment still has installed and compacts the index; --dry-run lists them without removing anything.

kosha daemon keeps one Kosha loaded, so repeated queries skip the few seconds it takes to load the embedding model. It prints {"ok": true, "status": "ready"}, then reads one JSON request per line from standard input, such as {"cmd": "context", "args": {"q": "embed a query"}}, and writes one JSON line per answer: {"ok": true, "result": ...} or {"ok": false, "error": "..."}. The commands are the keys of _DISPATCH below, and their arguments are those of the Kosha methods of the same names. kosha install copies SKILL.md into the repository for coding agents.

main is the entry point behind the kosha command. It looks up the subcommand in CMDS, parses the remaining arguments against that function’s signature, and calls it. With no subcommand, or an unknown one, it prints the list of subcommands.
