mcp

An MCP server that gives Claude, Codex and other MCP clients the kosha index as a set of tools.

The tools call the same Kosha methods as the command line and the daemon. The mcp package is a dependency of kosha, and nothing extra needs installing. kosha indexes the repository it starts in and that repository’s environment. Start the server at the project root, inside the project’s environment. uv run does both:

uv add --dev koshas
uv run kosha-mcp            # serves over standard input and output; add --http for Streamable HTTP

The server creates one Kosha on the first tool call and keeps it. The embedding model loads once per server and not once per call. The server converts results to plain JSON types before it returns them.

Index management

status reports whether the index is current. An agent should call it first. A stale index looks like missing code. sync updates the index with the same switches as Kosha.sync and returns the new status.

from fastcore.test import test_eq

    graph:bool=True, graph_mode:str='fast', graph_metrics:bool=True

Update the repo index, the package index and the call graph, then return the status; graph=False skips the graph.

def status()->dict:

How fresh the index is: {files, packages, graph_nodes, stale_files, stale_pkgs, new_files}; call it first and sync if anything is stale.

# `sync` passes `graph_mode` and `graph_metrics` to `Kosha.sync` unchanged.
_mcp_calls = []
class _McpKosha:
    def sync(self, **kwargs): _mcp_calls.append(kwargs)
    def status(self): return {'graph_nodes': 1}
_mcp_k, _k = _k, _McpKosha()
try: _mcp_status = sync(graph_mode='full', graph_metrics=False)
finally: _k = _mcp_k
test_eq((_mcp_calls[0]['graph_mode'], _mcp_calls[0]['graph_metrics']), ('full', False))
test_eq(_mcp_status['graph_nodes'], 1)

Search

context searches the repo and the packages together, with call-graph details on each hit. Use context by default. repo_context and env_context search one index. Call env_context before writing new code, to check whether a dependency already does the job. where_to_add suggests the file and line for new code.

Call graph

These tools take full dotted node names, such as fastcore.basics.merge, as found in a search hit’s mod_name. node_info returns a node’s callers, callees, co-dispatched peers and PageRank. A high PageRank means much of the code depends on the node. pkg_url returns the web address of an installed package, for looking up its documentation.

Connect a client

The server must start at the project root inside the project’s environment. Use uv run kosha-mcp. uvx kosha-mcp runs the server in a separate environment that does not have your project’s packages.

For Claude Code, run this inside the project:

claude mcp add kosha -- uv run kosha-mcp

For Codex, add this to ~/.codex/config.toml. Codex starts servers in your session’s working directory. Start Codex at the project root.

[mcp_servers.kosha]
command = "uv"
args = ["run", "kosha-mcp"]

Claude Desktop does not start in your project. Name the project in claude_desktop_config.json:

{"mcpServers": {"kosha": {"command": "uv", "args": ["run", "--project", "/path/to/your/repo", "kosha-mcp"]}}}
